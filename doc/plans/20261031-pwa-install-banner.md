# PWAのインストールを画面から案内する

## 目的

インストールの導線は、ブラウザ標準のUI（アドレスバーのアイコンやメニュー）だけである。
`20260729-pwa-general-user-only.md` で、アプリ内の導線は「様子を見る」として見送っていた。
標準のUIは気づかれにくく、iOS にはそもそも無い。
Push通知は iOS ではホーム画面に追加しないと届かないが、その案内は Push通知画面を開くまで出ない。

## 決めたこと

ダッシュボードの先頭に、閉じられるバナーを出す。サーバ側は変えない。

| 環境 | バナーの中身 |
|---|---|
| `beforeinstallprompt` が届いた（Chrome） | 「インストール」ボタン。押すとブラウザのダイアログが開く |
| `needs-install` と同じ条件（iOS Safari のタブ） | ホーム画面への追加の手順 |
| それ以外（インストール済み、アプリ内ブラウザ、Firefox など） | 出さない |

閉じたことは `localStorage` に端末単位で覚え、以後は出さない。
ブラウザのダイアログでキャンセルした場合も閉じたものとして扱う。
インストールをやめた人に同じ案内を出し続けないためである。

## 作り

### イベントはエントリで受ける

`beforeinstallprompt` はページの読み込み直後に一度だけ届く。
ログイン画面で開いてからログインすると、ダッシュボードの部品が描かれるより先に届いてしまう。
そのため `app.tsx` で受け取ってモジュールに保持し、hook は `useSyncExternalStore` で読む。

受け取った時点で `preventDefault` を呼ぶ。
Android の Chrome が自動で出すミニインフォバーとバナーが二重にならないようにするためで、閉じた後も呼び続ける。
閉じた人にミニインフォバーを出すと、断った案内がまた出るからである。

`prompt()` は1つのイベントにつき1回しか呼べない。呼ぶ前に保持を消す。
`appinstalled` でも消す。

### 判定を共有する

`isInstalledWindow` と `needs-install` の条件を `usePushSubscription` から `shared/lib/displayMode.ts` に移し、バナーと同じ判定を使う。
判定の振る舞いは変えない（既存のテストで確かめる）。

### 手順の文言を共有する

Push通知画面の手順を `AddToHomeScreenSteps` に切り出す。
見出しと2番目の手順だけ、画面ごとに渡す。

## 採らなかった案

**全画面に出す（`AppShell` に置く）。** ストックの編集中にまで割り込む必要がない。ログイン後に必ず通るダッシュボードで足りる。

**UA で iOS を判定する。** `20261018-ios-safari-push.md` で避けた方法である。既存の判定と揃えると、iOS 16.3 以前と macOS Safari 15 以前で案内が誤る点も同じ扱いで済む。

**閉じてから一定期間で再表示する。** 期間の根拠が無い。必要になってから足す。iOS では Push通知画面の案内が残り、Chrome ではブラウザ標準のUIが残るので、閉じても導線は消えない。

## テスト

jsdom にはイベントも `PushManager` も無いので、差し替えて確かめる。

- イベントが届けばボタンを出す。hook が描かれる前に届いたものも拾う
- ボタンでダイアログを開き、バナーが消える。キャンセルなら閉じた状態を残す
- 手順が出る条件は `needs-install` と同じ。単独ウィンドウでは出ない
- 閉じると再表示しない。`localStorage` が例外を投げても画面は壊れない
- `appinstalled` で消える

## 実機でしか分からないこと

- Chrome でイベントが届くこと。ページの操作と閲覧時間の条件があるので、初回はバナーが遅れて現れるはず
- ダイアログからインストールして、独立ウィンドウで開くこと
- iOS Safari のタブでバナーが出ること。ホーム画面から開いたときに出ないこと

## 追記：バナーをやめ、画面の下に浮かせたカードにする（2026-10-31）

ダッシュボードの先頭に置くバナーは、見せ方としていまいちだった。
`beforeinstallprompt` は遅れて届くので、現れたときに中身を押し下げる点も良くない。

画面の下に浮かせたカード（`InstallCard`）に変える。
スマホでは下部タブの上、PCでは右下に置く。
出す条件と、閉じた記録の扱いは変えない。

Chrome 向けのカードには「あとで」と「インストール」を並べ、右上に×を置く。
「あとで」も×と同じ扱いで、以後は出さない。

追加の実機確認：

- スマホで、カードが下部タブに重ならないこと
- 購入予定品の一覧の最後の行が、カードを閉じれば操作できること

## 追記：「あとで」を「今はしない」にする（2026-10-31）

押すと以後は出ないので、「あとで」では文言と動きが食い違う。動きは変えず、文言を「今はしない」にする。

## 追記：Chrome 向けカードの配置を直す（2026-10-31）

×の列があると、文言とボタンの右端が揃わない。「今はしない」と×は同じ動きなので、Chrome 向けのカードから×を外す。
ボタンは2等分の幅で横に並べ、文言は問いかけの形にする。手順のカードはボタンが無いので×を残す。
