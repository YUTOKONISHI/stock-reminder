# Adobe Color のテーマに配色を合わせる

## 経緯

`20260912-ui-design-refinement.md` は「配色は Adobe Color のトレンドか Hue 360 で決める」という規準に対し、現行がすでにトレンドの内側にあるとして主色を入れ替えなかった。
結果として、Adobe Color で作った配色はどこにも入っていなかった。

今回は Adobe Color で作成したテーマを出どころにする。

## 採用したテーマ

セージ `#5A7550` を基準色にしたマイ Color テーマ。

| テーマの色 | 白地とのコントラスト比 | 割り当て |
|---|---|---|
| `#5A7550` | 5.13:1 | `primary-600`（変更なし） |
| `#ABCA9F` | 1.80:1 | `primary-200` |
| `#D9D2CE` | 1.49:1 | `line` |
| `#85859E` | 3.59:1 | `line-strong` |
| `#F5B698` | 1.75:1 | そのままでは使わない。差し色 `urgent` の色相に使う |

`#F5B698` は白文字を載せるにも白地の文字にするにも明るすぎる。
色相だけを取り、現行の `urgent` と同じコントラスト比になる明度まで暗くした。
`#85859E` は入力欄の枠にそのまま使い、同じ色相を暗くして補足の文字色 `info-600` にも使う。

## 変更するトークン

| トークン | 変更前 | 変更後 | コントラスト比 |
|---|---|---|---|
| `--color-line` | `#e7e3dc` | `#d9d2ce` | 白地と 1.49:1 |
| `--color-line-strong` | `#8f8a80` | `#85859e` | 白地と 3.59:1、canvas と 3.44:1 |
| `--color-primary-200` | `#c7d9c1` | `#abca9f` | 白地と 1.80:1 |
| `--color-urgent-50` | `#fbf0ec` | `#fbf0eb` | ink と 12.59:1 |
| `--color-urgent-600` | `#b4553a` | `#ae5a32` | 白文字 4.87:1、canvas 上の文字 4.67:1 |
| `--color-urgent-700` | `#8f4229` | `#884728` | 白文字 7.05:1、urgent-50 上の文字 6.30:1 |
| `--color-info-600` | `#3f6e8c` | `#646496` | 白地 5.52:1、canvas 5.29:1 |

テーマに無い色（canvas、ink、ink-muted、disabled、primary の残りの段、danger、warning、success）は変えない。
`canvas` と `primary-600` が変わらないので、マニフェスト、theme-color、`offline.html`、進捗バー、アイコンには手を入れない。

## 採用しなかった案

比較資料: https://claude.ai/artifact/WbcPieqocRmTpXEhx4Jwtt

- カラーホイールの調和規則（トライアド、スクエア、補色、スプリットコンプリメンタリー）で色相を回す案。Adobe Color の画面で出した値ではなく近似計算だったため、実際のテーマが出た時点で外した。
- セージを含まないテーマ3案（主色を青緑、オリーブ、ブラウンにするもの）。主色と地が変わり、PWA の関連ファイルとアイコンの作り直しが要る。ブラウンの案は下部ナビの現在地が選択していない項目と見分けにくくなる。
- ピンクを差し色の元にするテーマ2案。白文字が読める濃さまで暗くすると、削除の赤 `#c0392b` と色相が 3° から 8° しか離れず、超過のバッジと削除が同じ意味に見える。
