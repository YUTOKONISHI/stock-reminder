# 購入時にストック数を入力する

## 背景

ダッシュボードの「買った」を押すと、次回購入予定日が「今日 + 消費日数 × ストック数」に進む。
ストック数は変わらないので、前回と違う数を持っていても前回の数で計算される。
消費日数30日、ストック数2の商品は、手元が1個でも予定日が60日後になり、在庫が切れてから1か月遅れて通知される。

## 決めたこと（2026-10-31）

- 「買った」を押すと、ストック数の入力欄があるダイアログを開く
- 入力するのは「購入後のストック数」とする。残っていた分も含めた手元の合計である
- 初期値は現在のストック数とする。普段どおりならそのまま確定できる
- 入力欄の両側に `-` と `+` のボタンを置き、直接入力もできるようにする。下限はストック数の登録や編集と同じ1とする
- 入力に合わせて次回購入予定日をダイアログに表示する
- 確定すると、ストック数を入力値で更新し、次回購入予定日を「今日 + 消費日数 × 入力値」に進め、`last_purchased_on` に今日を入れる
- 確定後はダイアログを閉じ、トーストで次回購入予定日を知らせる
- キャンセルでは何も変えない。開き直すと入力値は現在のストック数に戻る
- 購入後の表示（`isHiddenAfterPurchase`）と通知の条件は変えない

ストック数は入力値に置き換わるので、購入時に1を入れた商品はダッシュボードで優先表示される。

## 今回入れないこと

- 残りのストック数を予定日から逆算して表示すること。ストック数は購入時と編集時にだけ変わり、時間の経過では減らない

## 採らなかった案

- **買った個数を入力する**：店頭では答えやすい。しかし、残っていた分を予定日に反映するには `max(今日, 現在の予定日)` を起点にする計算が要り、初期値に使う前回の購入数を保存する列も要る
- **今のまま1回押すだけにする**：操作は少ないが、持っている数の変化を記録できず、背景のずれが残る

| テスト | `StockControllerTest` と `dashboard.test.tsx` の購入の検証を新しい動作に直し、ダイアログのテストを足す |
| 要件定義書、設計書 | `AGENTS.md` と `doc/design/stock.md` の「ストック数は変えない」を直す。`doc/design/stock.md` の「買い物かごのボタン」も実際の「買った」に直す |
