## 最初に直す候補

A1、A2、B1、C1、C2 を勧める。

## A. 中心機能のずれ

### A1. 編集しても予定日が再計算されない

`useStockForm.ts` が、編集画面の日付欄に現在の予定日を入れる。
送信すると手動の上書きとして扱われるので、ストック数や消費日数を変えても予定日は変わらない。
自動で算出するには、利用者が日付欄を手で空にする必要がある。

### A2. 「残りN個」が時間で減らない

`quantity` は入力時の値のままで、減らす処理が無い。
ストック一覧の表示が実態とずれ、ダッシュボードの「ストック数1を優先」も手入力の値にしか効かない。

### A3. 世帯で共有できない

ストックは利用者ごとに持つ。
README の「夫婦や同居人のいる世帯向け」と、ペルソナの「夫婦別々に買ってしまう」を解決できていない。
製品として最大の不足である。

### A4. 早めに買うと記録しにくい

購入ボタンはダッシュボードの購入予定品（原則7日以内）にしかなく、ストック一覧には無い。
編集で代用すると A1 に当たる。

### A5. 買い物の場面に合う機能が足りない

- 通知は当日と超過分だけで、週末のまとめ買いに使える予告が無い
- ストック一覧に検索とカテゴリの絞り込みが無い
- カレンダーの枠を押しても商品が分からず、8日以上先の予定は商品名を確認しにくい

### A6. 導線と登録の手間

- ストック管理が「設定」の下にある
- 初期登録は1件ずつである
- マスタに無い商品は登録できない

## B. 不具合と信頼性

### B1. ログアウトしても端末の購読が残る

`shared/lib/auth.ts` の `logout` は購読を解除しない。
前の利用者の通知が届き続ける。
別の利用者には、購読が無いのに通知が ON と表示される。

### B2. 購読の失敗が分からない

`usePushSubscription.ts` に例外処理が無く、サーバへの保存結果を待たずに ON にする。

### B3. iOS の Push が実機で未検証

スマホでの利用を想定するなら、早めに確かめる必要がある。

### B4. 未読通知が増え続ける

- 超過中は毎日1件増え、購入しても過去の未読は残る
- 一括既読が無い
- 古い履歴の削除が無く、`notification_logs.user_id` にインデックスも無い

### B5. 朝の通知が止まっても気づけない

`app:send-purchase-reminders` は送信に失敗しても `SUCCESS` を返す。
死活監視も、9時を逃した場合の再実行も無い。

### B6. エラー時の画面が未整備

- 403、404、419、500 の専用画面が無い
- 通信失敗時の処理が無く、オフラインで購入を押しても案内が出ないと見られる

### B7. 2時間でログアウトされやすい

`fly.toml` に `SESSION_LIFETIME` の指定が無く、secrets にも無ければ既定の120分になる。
ログイン状態を保持する機能も無い。

### B8. 二重送信を防げていない

`useStockForm` の `submit` が Promise を返さないため、「保存中...」が事実上表示されない。
購入ダイアログにも送信中の無効化が無い。

### B9. 入力値に上限が無い

`quantity`、消費日数、世帯人数が対象である。
巨大な値を送ると、整数や日付の範囲を超えて500エラーになる恐れがある。

### B10. パスワード忘却でメールアドレスの大文字を区別する

登録時は小文字化されるが、`PasswordResetController` は入力のまま検索する。
大文字を含めて入力するとメールが届かず、画面には「送信しました」と出る。

## C. セキュリティ

### C1. Push の宛先が任意の文字列で通る（SSRF）

`PushSubscriptionController` は `endpoint` を文字列としてしか検証しない。
登録した利用者なら内部 URL を指定でき、毎朝 scheduler がそこへ POST する。
https と既知の Push サービスに限定する。

### C2. Push の秘密鍵がログに残る

`LogRequest` の伏せ字の対象に `keys.auth`、`keys.p256dh`、`endpoint` が入っていない。

### C3. パスワードを変更しても他の端末のセッションが切れない

盗まれたセッションがそのまま使える。

### C4. セキュリティヘッダが無い

CSP、HSTS、`X-Frame-Options` の設定が、アプリと Docker 関連のファイルに見当たらない。

### C5. 使っていない2要素認証が有効

Fortify のルートは公開されているが、`User` に必要な trait が無く、`two_factor_*` も隠していない。
機能ごと無効にする。

### C6. メール確認が無い

他人のアドレスでも登録でき、入力を間違えるとパスワードを再設定できない。

## D. 保守

### D1. E2E テストが無い

ログイン、ストック登録、購入を通しで確かめるテストが無い。
Playwright の追加と CI の実行時間の増加を伴うので、別の計画で扱うと決めた。
