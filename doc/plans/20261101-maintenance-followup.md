# 保守の積み残しを片付ける

## 目的

アプリの点検で見つかった保守の問題のうち、利用者の操作を増やさずに直せるものをまとめて片付ける。

## 決めたこと

| 項目 | 変更 |
|---|---|
| `stocks.next_purchase_date` | `timestamptz` から `date` に変える。既存の値は `Asia/Tokyo` の日付に変換する |
| カテゴリ名 | DB の一意制約を足す |
| 商品名 | カテゴリをまたいで一意にする。DB の制約と管理画面の検証を足し、重複のエラーをトーストに出す |
| Service Worker の `VERSION` | 手で上げるのをやめ、`PwaController` が配信時に埋める |
| CI | `lint.yml` のジョブを `tests.yml` に移し、lint が落ちたらデプロイしない |
| 片付け | 設計書のずれ、シーダーのコメントの古いパス、`AppServiceProvider` のコメントアウト、`inspire` コマンド |

`VERSION` は `20260729-pwa-general-user-only.md` で、デプロイ先が決まるまで手で上げるとしていた。
デプロイが自動化された後も `v1` のまま上げられていなかったので、手順から外す。
値は Vite のマニフェストとオフライン画面のハッシュから作る。

## 採らなかった案

**商品名をカテゴリの中でだけ一意にする。** 同じ物が別の商品として並び、利用者が二重に登録できてしまう。シーダーも商品名だけで同一と見なしている。

**`deploy.yml` が `linter` と `tests` の両方を待つ。** `workflow_run` はワークフローごとに起動するので、両方の成功を待つには判定の処理を別に書くことになる。

**`VERSION` を Vite で埋める。** `sw.js` は Vite の処理対象外で、埋めるための仕組みが別に要る。

## 本番への影響

本番に同じ名前のカテゴリか商品があると、`release_command` のマイグレーションが失敗し、デプロイは止まる。
旧版は動き続けるので、管理画面で名前を直してからデプロイし直す。

配布後の最初のアクセスで Service Worker が入れ替わり、`v1` のキャッシュが消える。

## 対象外

- E2E テストは別の計画で扱う
- drawSQL の図は手で更新し、エクスポートし直す
