# 全画面のデザイン改訂

## 経緯

デザインの拠り所を次のように定めた依頼を受けた。

- レイアウトは TailwindCSS の Container / Spacing / Flexbox & Grid だけで組む
- 装飾は TailwindCSS 製の UI コンポーネント集に寄せる
- 余白は 8 の倍数、文字は 16px を基準に 4 の倍数
- フォントは Google Fonts から和文と欧文を 1 種類ずつ
- 配色は Adobe Color のトレンドか Hue 360 で決める
- 素材は写真 O-DAN、イラスト freepik、アイコン FontAwesome か icomoon

現行は `20260725-ui-color-palette.md` でセマンティックトークンに一元化済み、`20260802-shadcn-ui-adoption.md` で shadcn/ui を導入済み。本計画はその上に上記の規準を当て、あわせて全画面の構成そのものも直す。

対象はトップ、ログイン、新規登録、パスワード忘却、パスワード再設定、ダッシュボード、Push通知、ストック管理、ストック編集、設定、個人情報の変更、管理者用ログイン、管理者用マスタ。

比較資料（提案時に作成し承認を得たもの）: https://claude.ai/code/artifact/e2b4adc8-fe85-4c82-a353-9745e4bc74b6

## 調査で分かったこと

決定を左右した事実を 3 つ残す。

### 1. 現行の配色はすでにトレンドの内側にある

2026 年の UI 配色はセージグリーン、テラコッタ、黄土、クレイ、ストーングレーといった土の色が中心で、Pantone の今年の色も温かみのあるオフホワイト（Cloud Dancer）である。現行の「ウォームニュートラル地 + セージグリーン」はその中心にあり、Adobe Color から引き直しても同じ方向に着地する。

よって主色を入れ替えるのではなく、彩度と明度を寄せる調整に留め、差し色を 1 色足す。

### 2. Bunny Fonts は和文に使えない

現行の `vite.config.ts` は `bunny('Instrument Sans')` を使っている。同じ `bunny()` で Zen 角ゴシック New を引くと `@font-face` が 366 個に分かれるのに `unicode-range` が 9 個しか付かない。ブラウザは必要な文字を判別できず全サブセットを取得する。

Google 側は 363 個すべてに `unicode-range` が付く。したがって和文は `google()` を使う。

### 3. lucide は shadcn の生成物に埋まっている

`ui/dialog.tsx` `ui/select.tsx` `ui/calendar.tsx` `ui/sonner.tsx` の 4 ファイルが内部で lucide を import している。ここを書き換えても `shadcn add` のたびに戻る。

FontAwesome に載せ替えるのは自分で書いた 9 ファイルに限り、shadcn 生成物は lucide のまま残す。lucide は依存から外れず、両方が入った状態になる。

## 決めたこと

### 配色

| トークン | 現行 | 改訂 | 白文字とのコントラスト比 |
|---|---|---|---|
| `--color-primary-600` | `#547048` | `#5A7550` | 5.13:1 |
| `--color-primary-700` | `#435a3a` | `#465C3F` | 7.33:1 |
| `--color-primary-100` | `#e6ede2` | `#E4ECE1` | ink と 11.66:1 |
| `--color-urgent-600` | 無し | `#B4553A` | 4.88:1 |
| `--color-urgent-700` | 無し | `#8F4229` | 7.05:1 |
| `--color-urgent-50` | 無し | `#FBF0EC` | ink と 12.59:1 |

主色は明度 +3、彩度 −2 の調整である。単体では現行と区別が付かない幅で、並べて初めて分かる。

トークン名は `accent` ではなく `urgent` にした。shadcn が `--color-accent` を淡いホバー地の意味で先に使っており、`bg-accent`（primary-50）と `bg-accent-600`（テラコッタ）が別物のまま同居してしまうため。

差し色の用途は「今日が予定日のもの」と「予定日を過ぎたもの」に限る。赤の `danger` は削除など取り消せない操作に残し、役割が重ならないようにする。`warning`（黄土）は現状の用途のまま触らない。

文字は 4.5:1、操作できる要素の境界は 3:1 を下限として全ペアを計算し、満たすことを確認した。

### フォント

和文 Zen 角ゴシック New、欧文 Roboto。どちらも `google()` でセルフホストする。`Instrument Sans` は外す。

Roboto を当てるのは日付と件数など桁の揃う数字に限る。地の文は和文書体で通す。

セルフホストを選ぶのは、PWA のオフライン画面でも字体が出るのと、外部への接続が増えないため。代償としてビルド成果物に和文 363 ファイルが入る。

### 文字サイズ

16px を基準に 4 の倍数とし、12 / 16 / 20 / 24 / 32 の 5 段にする。

| 現行 | 改訂 | 使用箇所 |
|---|---|---|
| `text-sm` 14px | 16px | 64 |
| `text-xs` 12px | 据え置き | 14 |
| `text-lg` 18px | 20px | 5 |
| `text-xl` 20px | 据え置き | 8 |
| `text-2xl` 24px | 据え置き | 1 |
| `text-3xl` 30px | 32px | 2 |

`app.css` の `@theme` で `--text-*` を上書きするため、クラス名は変えずに値だけ移る。本文が 14px から 16px に上がるので和文は読みやすくなるが、行の高さが伸びる。影響が大きいのは通知一覧と管理画面の表で、およそ 1 割伸びる。

### 余白

8 / 16 / 24 / 32 / 48px を使う。`p-5`（20px）、`py-3`（12px）、`px-3`（12px）、`mb-3`（12px）などを 8 の倍数に寄せる。

4px は半段として残す。対象はアイコンと文字の間隔（`gap-1`）に限る。ここを 8px にすると語とアイコンが離れて別の要素に見えるため。

### コンポーネント化

`shadcn add card` で Card を入れ、`rounded-lg border border-line bg-surface p-4` の直書き 11 箇所を置き換える。ページ側に残るのは Container / Spacing / Flexbox & Grid の指定だけにする。

`shadcn add` は色定義を書き足すことがある。実行後に `app.css` の差分を必ず見る（`20260802-shadcn-ui-adoption.md` の注意事項）。

### 画面ごとの構成

要件定義書の決まりはいずれも変えない。見せ方だけを変える。

#### ダッシュボード

4 種類のカードがすべて同じ枠・角丸・背景で並び、いちばん急ぐ「今日買うもの」が他の情報に埋もれている。

1. 購入予定品を 2 列カードから 1 列の行に変える。現行は商品名が長いと折り返して高さが揃わない。行にすると商品名・期限・ボタンが縦に揃う
2. 今日のものだけ枠と敷き色を `urgent` にし、「今日」の印を付ける
3. 購入ボタンに「買った」と書く。現行はカートの絵だけで、押すと何が起きるか分からない
4. 「あと 2 日」を添える。日付だけでは急ぎ具合が分からない

上部の 3 枚のタイルは 1 枚にまとめ、次回購入日を主、件数 2 つを従として並べる。今日の件数だけ差し色にする。

カレンダーは全件の予定日に枠を出す決まりを保つ。今日が予定日のマスだけ差し色にして、下の一覧と色を揃える。

#### トップ

説明が 3 行続くだけで、何をするアプリなのかが読み終わるまで分からない。「買ったときに登録する」「次に買う日が決まる」「その日の朝に知らせる」の 3 段に分け、アイコンを添える。

アイコンを `rounded-full` で円に切っているのをやめる。角丸 22% で焼いた意匠の角が削れている。ボタンの角丸もこの画面だけ `rounded`（4px）なので 8px に揃える。

#### ログインと新規登録

トップから来るとアプリの印がいったん消える。印と名前を上に置く。`AuthCard` は影だけで枠が無く他画面のカードと質感が違うので、枠を付ける。

2 つのリンクが同じ大きさで両端に分かれている。ここに来る人の多くは新規登録なので、そちらを上に大きく置き、パスワード忘却を下に小さく置く。

入力欄の高さを 36px から 40px にする。文字が 16px に上がるため。

#### Push通知

通知 1 件が日付・題・本文の順で、最初に目に入るのが日付になっている。題を先に出し、日付は最後に回す。既読ボタンに「既読」の語を添える。

通知設定のトグルは `button` と `span` の手書きで、焦点の枠も自前で当てている。`shadcn add switch` に置き換える。「有効にする」だけでは何がいつ届くか分からないので、朝 9 時であることを添える。

#### ストック管理

1 件が 3 行に積まれ、うち 2 行が「次回購入予定日:」「ストック数:」というラベルで始まっている。ラベルを外して 2 行に詰め、残り 1 個のものに印を出す。並び順は変えない。

見出しの「管理項目」を外す。画面名がすでに「ストック管理」で、中身は管理項目ではなくストックそのもの。件数に置き換える。

追加ボタンは一覧の下端にあり、件数が増えるほど遠のく。画面に固定する。全角の「＋」はアイコンにする。

空のときは「登録されているストックはありません」で終わっており、どこから登録するか書いていない。追加への導線を置く。

#### 設定

項目名だけが並んでいる。何が変えられるのか分かるよう、一行の説明を添える。

#### 入力フォーム（ストック編集・個人情報の変更・新規登録）

入力欄はすでに shadcn の Form と Input に寄せてあるので、2 点だけ変える。

- キャンセルが上、保存が下になっている。押す機会の多い保存を上に置く
- ストック編集の「このストックを削除」は枠の無い文字だけで、他のリンクと見分けが付かない。枠線を付けて赤で示す

#### 管理者用マスタ

操作ボタンだけ `rounded-full` の丸型で、本体の角丸 8px と揃っていない。行の高さと余白も 12px 刻みになっている。

「変更」が塗りつぶしのボタンで、行ごとに緑が並んで表が騒がしい。枠線のボタンに下ろし、色は削除の赤だけ残す。全角の「＋ 追加」はアイコンにする。

## 手順

1. FontAwesome を導入する（`@fortawesome/fontawesome-svg-core` / `free-solid-svg-icons` / `react-fontawesome`）
2. `vite.config.ts` のフォントを `google()` の Zen 角ゴシック New と Roboto に差し替える
3. `app.css` に配色の調整、`urgent` の追加、`--text-*` の上書き、`--font-sans` と `--font-numeric` の定義を入れる
4. `shadcn add card switch` で Card と Switch を入れ、直書き 11 箇所と手書きトグルを置き換える
5. アイコンを 9 ファイル分載せ替える
6. 画面を順に直す。ダッシュボード → ストック管理 → Push通知 → 設定 → トップ → 認証系 → 入力フォーム → 管理者用マスタ
7. 全画面の余白を 8 の倍数に寄せる
8. PWA アイコン 6 点を焼き直し、`manifest.webmanifest` と `offline.html` と `app.blade.php` の色を合わせる
9. `README.md` に FontAwesome の帰属を書く

# 追記（2026-09-12）：実装で分かったこと

計画時に見えておらず、実装で手当てが要った点を残す。

## 1. 差し色のトークン名を `urgent` にした

`accent` は使えない。shadcn が `--color-accent` を「淡いホバー地」の意味で先に使っており、`bg-accent`（primary-50）と `bg-accent-600`（テラコッタ）が別物のまま同居してしまう。`--color-urgent-50/600/700` にした。

## 2. `preload` の既定が全WOFF2で、`unicode-range` の意味が消える

`laravel-vite-plugin` のフォント設定は `preload` の既定が `true`（全WOFF2を先読み）である。和文だと363ファイルすべてに `link[rel=preload]` が出て、ブラウザが必要な字だけ取る仕組みが働かない。`preload: false` にした。

`subsets` を `['japanese', 'latin']` に絞ってもファイル数は減らない。Google の和文は元から120前後のサブセットに割れているため。

## 3. `@fonts` はCSSを全文インラインで出す

`Vite::fonts()` は `<style>` タグとして CSS を書き出す。外部ファイルへの `<link>` ではない。和文3ウェイトで 390 個の `@font-face`、324KB（gzip 89KB）がHTMLに乗る。

Inertia なので全体の読み込みは初回とハードリロードのときだけで、画面遷移では発生しない。Service Worker も必要になった資産だけを都度キャッシュする作りなので、4.3MB が一括で落ちることはない。

ウェイトを 400/700 の2種に減らすと 269 個・gzip 60KB まで下がるが、shadcn の Label / Input / Button が `font-medium`(500) を使っており、外すと無言で400に落ちてボタンが軽く見える。3ウェイトのままにした。

## 4. Tailwind v4 は `border-color` の既定が `currentColor`

色を書いていない `border` が文字色（ink）で描かれ、黒枠になる。shadcn の Card・Dialog・SelectContent が色なしの `border` を使うため、カードの枠が全部黒く出ていた。v3 の既定は `gray-200` で、shadcn はその前提で書かれている。

`app.css` の `@layer base` で既定を `--color-line` に戻した。個々の生成物を直すと `shadcn add` で戻るため。

## 5. `shadcn add` が `cn` の解決を誤る

`card` と `switch` の生成物が `import { cn } from "cn"` になり、無関係な npm パッケージ `cn@0.3.0` まで依存に追加された。既存7件は `@/shared/lib/utils` である。import を直し、パッケージを外した。`shadcn add` のあとは生成物の import と `package.json` も見ること。

## 6. 主色の二重管理は4箇所ではなく5箇所だった

`app.css` のコメントが挙げていた manifest / blade / offline.html / アイコンに加えて、`app.tsx` の Inertia 進捗バーにも `#547048` が直書きされていた。コメントに追記した。

## 7. カレンダーの「過ぎた日」を差し色にした

計画では今日だけを差し色にするつもりだったが、実装して見ると、同じ日が一覧では「2日超過」の差し色、カレンダーでは緑の枠になって食い違う。過ぎた日も差し色にした。

## 8. 高さを8の倍数に揃えた

shadcn の既定は Button `h-9`(36px)、Input `h-9`、SelectTrigger `h-9` で、いずれも8の倍数から外れる。40px に揃えた。`icon` は 36→40、`lg` は 40→48。

## 9. 商品名は折り返す

`truncate` を当てていたが、モバイル幅で「ミネラルウォータ…」と切れた。行の高さは内容に合わせればよいので、折り返しにした。

## 残っている論点

**「次回購入日」が過去の日付を出す。** 全ストックの `next_purchase_date` の最小値なので、予定日を過ぎたものがあると過去の日付が「次回購入日」として大きく出る。改訂前からの挙動だが、超過を差し色で見せるようにした分だけ目立つ。過ぎたものを除いて最も近い未来の日付を出すか、「2日超過」と併記するかは要件の判断が要るため、本計画では触っていない。

## 検証の実際

雛形以外のテストが無く（`tests/` は `ExampleTest` 2件のみ）、`ci:check` は変更箇所を覆わない。Chrome for Testing をコンテナに入れ、CDP 経由で全画面のスクリーンショットを撮って目視した。上の 4・7・9 はそれで見つけた。

## 10. フッターのボタンを4等分にした（2026-09-12 指摘対応）

`justify-around` で並べていたため、ボタンの中心が均等に並ばなかった。`justify-around` は各要素の幅が違うと余白の配り方が不揃いになる。ラベルが「ダッシュボード」7文字と「通知」2文字では幅が倍以上違う。

各ボタンに `flex-1` を当てて4等分にした。

あわせてラベルを「ダッシュボード」から「ホーム」に縮めた。`flex-1` にすると1枠は画面幅の1/4になり、320px 幅では「ダッシュボード」が2行に折れてフッターの高さが変わる。画面名はヘッダーと見出しに出ているので、タブで繰り返す必要はない。折り返しの保険に `whitespace-nowrap` も付けた。

## 11. ストック管理に戻る導線を足した（2026-09-12 指摘対応）

ストック管理は設定の下の階層にあるが、画面の中に親へ戻る手がかりが無く、フッターの「設定」を押すしか道が無かった。モバイルで中央寄せの見出しを出しているぶん、左端の戻る矢印が無いのが目立つ。

`AppShell` に `backHref` を足した。渡すと、デスクトップはヘッダーの画面名の左に、モバイルは見出しの左に戻る矢印が出る。モバイルの見出しはこのとき `AppShell` 側で描くので、ページの `h1` は外す。

ストック追加・ストック設定・個人情報の変更も下の階層だが、いずれも「キャンセル」で親に戻れるため今回は触っていない。揃えるなら同じ `backHref` を渡せばよい。

あわせて、追加ボタンが画面に固定されていて最後の行に重なっていたので、一覧の下に余白を足した。

## 12. 入力フォームのキャンセルを外した（2026-09-12 指摘対応）

11 でストック管理に戻る矢印を足した結果、キャンセルで戻るフォーム画面と作りが揃わなくなった。ストック追加・ストック設定・個人情報の変更にも `backHref` を渡し、キャンセルボタンを外した。戻る道は矢印に一本化する。

矢印は画面の上端にあるので、長いフォームでは下まで送ったあと戻るのに上まで戻る必要がある。実機幅で測ったところ、個人情報の変更は矢印から保存まで約 830px で iPhone の 844px に収まり、ストック設定（削除ボタンがあるぶん最も長い）でも少し送る程度だったため、ヘッダーの固定はしていない。

商品が無いときの「一覧に戻る」は、その画面で唯一の導線なので残した。

## 8 の続き：8 の倍数から外れる余白の扱い

`p-1.5`（カレンダーの円の内側）は残した。これは要素の間隔ではなく、背景を枠の内側に切り詰めるための値で、8 の倍数にすると円が枠に重なる。

## 13. 「次回購入日」が過去の日付を出す件（2026-09-12 決定）

「残っている論点」に挙げた件を決めた。**超過があるときは見出しごと言い換える**（比較資料の案2）。
比較資料: https://claude.ai/code/artifact/9d00024c-55bf-4e96-a114-1441474671d5

| | 超過なし | 超過あり |
|---|---|---|
| 見出し | 次回購入日 | **買い忘れ**（差し色・太字） |
| 日付 | ink | 差し色 |
| 印 | 無し | 「2日超過」 |

日付そのものは全件の最小値のままで、計算は変えない。変えるのは見出しと色だけ。「次回購入日」という言葉と過去の日付が食い違うのが問題だったので、言葉のほうを状況に合わせる。

採らなかった案と理由。

- **過ぎたものを除いて最も近い未来を出す**。超過が画面から消える。3件買い忘れているのに「次回は9月28日」と出ると、やることが無いように読める
- **日付をやめて「あと何日」を主にする**。行動には直結するが、大きい文字が日付でなくなるとカレンダーとの対応が弱まる。要件定義書の「次回購入日とカレンダーを表示」からも離れる

### あわせて直した件数の数え方

`今日` は当日ちょうどのものだけを数えていたため、超過したものがあっても `0` と出て、急ぐものが1件も無いように読めた。超過分は `1週間以内` に埋もれていた。

`今日まで` に改め、予定日を過ぎたものも含めて数える。過ぎたものは今日買うべきものなので、同じ数字でよい。
